# ریشه | Rishe

**ریشه** یک فرهنگ واژگان انگلیسی به فارسی است که به‌جای نمایش معنی واژه به‌تنهایی، ارتباط آن با واژه‌های هم‌خانواده و ساختار واژه را نیز نشان می‌دهد. هدف پروژه این است که یادگیری واژگان با شناخت پایه‌ها، پیشوندها، پسوندها و ارتباط میان واژه‌ها ماندگارتر شود.

- **مخزن پروژه:** https://github.com/mosep18/rishe
- **نسخهٔ درج‌شده در برنامه:** `1.6.2`
- **فناوری‌ها:** HTML، CSS، JavaScript خالص و داده‌های واژگانی JSON
- **نوع برنامه:** وب‌اپلیکیشن سبک با پشتیبانی از PWA و استفادهٔ آفلاین پس از بارگیری منابع لازم

## امکانات

### واژه‌نامه و ساختار واژه

- جست‌وجوی واژه‌های انگلیسی و مشاهدهٔ معنی فارسی و اطلاعات دستوری موجود.
- مشاهدهٔ خانوادهٔ واژگانی و ارتباط واژه با پایه یا ریشهٔ ثبت‌شده.
- بررسی پیشوندها، پسوندها و الگوهای ساخت واژه.
- نمایش مثال در صورت تطبیق مثال با خودِ واژه؛ مثال یک واژهٔ هم‌خانواده لزوماً برای واژهٔ جاری نمایش داده نمی‌شود.
- برچسب‌گذاری بعضی مدخل‌ها به‌عنوان پیش‌نویس، در مواردی که اطلاعات هنوز به بازبینی نیاز دارد.

### تمرین و یادگیری

- ذخیرهٔ واژه‌ها برای مراجعه و تمرین بعدی.
- تمرین با فلش‌کارت و آزمون چندگزینه‌ای.
- برنامهٔ روزانه با هدف قابل تنظیم برای معرفی واژه‌های جدید.
- مرور فاصله‌دار با ارزیابی یادآوری واژه و تعیین زمان مرور بعدی.
- نمایش آمار یادگیری، مرورها و فعالیت روزهای اخیر.
- ساخت مجموعه‌های شخصی برای موضوع‌هایی مانند انگلیسی هوانوردی، واژه‌های دشوار یا آمادگی آزمون.
- تنظیم یادآور روزانه، در مرورگرهایی که اعلان وب را پشتیبانی می‌کنند.

### نگهداری داده و دسترسی آفلاین

- ذخیرهٔ تنظیمات و پیشرفت یادگیری در حافظهٔ محلی مرورگر.
- خروجی‌گرفتن از داده‌های کاربر در قالب JSON و واردکردن آن‌ها در برنامه.
- استفاده از Service Worker برای کش‌کردن منابع ضروری و فراهم‌کردن امکان استفادهٔ آفلاین پس از بارگیری اولیه.
- رابط کاربری با متن‌های فارسی و انگلیسی در بخش‌های مختلف برنامه.

## اجرای محلی

پروژه به نصب بسته‌های npm یا ساخت (build) نیاز ندارد. کافی است Python 3 یا یک وب‌سرور محلی در اختیار داشته باشید.

```bash
git clone https://github.com/mosep18/rishe.git
cd rishe
python -m http.server 8000
```

سپس این نشانی را در مرورگر باز کنید:

```text
http://localhost:8000/
```

در ویندوز، در صورت تنظیم‌بودن لانچر Python، می‌توانید از `py -m http.server 8000` نیز استفاده کنید. راه دیگر، اجرای پوشهٔ پروژه با افزونهٔ **Live Server** در Visual Studio Code است.

برای نصب به‌شکل PWA، برنامه باید از یک مبدأ امن مانند `localhost` یا یک وب‌سایت دارای HTTPS باز شود. بازکردن مستقیم فایل `index.html` با مسیر `file://` برای آزمودن Service Worker مناسب نیست.

## حریم خصوصی و محدودیت‌ها

- پیشرفت، واژه‌های ذخیره‌شده و تنظیمات یادگیری روی همان مرورگر و دستگاه نگهداری می‌شوند؛ حساب کاربری یا همگام‌سازی ابری در معماری فعلی وجود ندارد.
- اگر داده‌های مرورگر پاک شوند، ممکن است داده‌های محلی برنامه نیز از دست بروند. پیش از تعویض مرورگر یا دستگاه، از بخش یادگیری خروجی JSON بگیرید و آن را در محل امنی نگه دارید.
- یادآور روزانه به اجازهٔ اعلان مرورگر نیاز دارد. یادآور هنگام بازبودن Rishe بررسی می‌شود؛ بدون زیرساخت Push، نمایش اعلان پس از بسته‌شدن کامل برنامه یا مرورگر تضمین‌شده نیست.
- همهٔ مدخل‌های واژگان لزوماً از نظر معنی، نقش دستوری یا ریشه‌شناسی بازبینی انسانی نشده‌اند. وضعیت پیش‌نویس را با محتوای تأییدشده یکسان در نظر نگیرید.

## ساختار اصلی پروژه

| فایل یا پوشه | کاربرد |
|---|---|
| `index.html` | نقطهٔ ورود برنامه، فراداده و ساختار اصلی صفحه |
| `app.js` | منطق رابط کاربری، جست‌وجو، فرهنگ واژگان و جریان‌های یادگیری |
| `styles.css` | ظاهر، چیدمان واکنش‌گرا و تم برنامه |
| `data.json` | داده‌های واژگان، خانواده‌ها و اطلاعات مرتبط |
| `manifest.webmanifest` | تنظیمات نصب وب‌اپلیکیشن (PWA) |
| `sw.js` | کش منابع و پشتیبانی آفلاین |
| `fonts/` | فونت‌های محلی برنامه |
| `icons/` | آیکون‌ها و تصاویر مورد استفادهٔ برنامه |
| `tools/` | ابزارهای کمکی پروژه، در صورت نیاز به اعتبارسنجی یا نگهداری داده |

## مشارکت و گزارش مشکل

برای گزارش خطا یا پیشنهاد به مخزن [Issues](https://github.com/mosep18/rishe/issues) مراجعه کنید. در گزارش مشکل، نسخهٔ برنامه، مرورگر و سیستم‌عامل، مراحل بازتولید خطا و نتیجهٔ مورد انتظار را بنویسید؛ اطلاعات شخصی یا فایل پشتیبان یادگیری خود را منتشر نکنید.

برای مشارکت در کد، تغییرات را محدود و قابل بررسی نگه دارید، وابستگی جدید را بدون نیاز فنی اضافه نکنید و هنگام تغییر ساختار داده، سازگاری با داده‌های ذخیره‌شدهٔ کاربران و عملکرد آفلاین را بررسی کنید.

## واژه‌شناسی و کیفیت داده

خانوادهٔ واژگانی باید بر پایهٔ ارتباط زبانی قابل دفاع ساخته شود؛ شباهت ظاهری یا املایی به‌تنهایی اثبات‌کنندهٔ ریشهٔ مشترک نیست. داده‌های تولیدشده یا ناقص باید پیش‌نویس باقی بمانند تا پس از بررسی مناسب، وضعیت آن‌ها تغییر کند.
